# HY V4 iHC pre: H100, hidden=3072

The H100 fast path uses the token tiling and split reductions from FlagGems-vllm, with a schedule measured for four residual channels and hidden size 3072. Other input shapes and devices retain the existing implementation. The post operator is unchanged.

## Schedule

| Tokens | K tile | Output tile | Output warps | Prefill splits |
| ---: | ---: | ---: | ---: | --- |
| 1–127 | 512 | 256 | 1 | decode |
| 128–255 | 512 | 1024 | 4 | decode |
| 256–511 | 128 | 1024 | 4 | existing |
| 512–2047 | 128 | 1024 | 4 | existing ×2 |
| 2048–4096 | 128 | 2048 | 4 | existing ×3 |
| Above 4096 | 128 | 1024 | 4 | existing |

Prefill uses eight tokens per tile, one warp, and three pipeline stages. FP32 accumulation and separate multiply/add rounding are preserved. Triton 3.6 caches compiled launch handles and scalar metadata, including the device, dtype, tile sizes, and warp count; buffers are never retained. Compilation and other Triton versions use regular JIT launches. The GPU-name predicate is treated as constant per device during tracing.

## Validation and results

Hardware: NVIDIA H100 80GB HBM3. Software: PyTorch 2.8.0a0+5228986c39.nv25.05, Triton/FlagTree 3.6.0, CUDA 12.9. Baseline: upstream commit `4c1ddc6d9f38230bad4daa4844219a3ca3765673`.

The transplanted public callable passed 74 standalone correctness cases covering FP16/BF16, empty inputs, schedule boundaries, strided inputs, unchanged paths at hidden 4096/6144 and three channels, repeated calls, and an independent FP64 reduction/projection reference. The 16 BF16 benchmark sizes also match upstream. Validation used isolated imports for the kernel source because the full vLLM package is not built in this environment. Full-model serving/evaluation was not run. A `torch.compile(fullgraph=True)` check reached the Triton backend after fixing the metadata predicate, but failed because this PyTorch build expects `triton.runtime.jit.specialize_impl`, which FlagTree 3.6.0 does not expose. The untouched upstream implementation reproduces the same failure; full compilation is not validated in this environment.

## Reproduce in a built vLLM environment

Save the baseline source, then run the comparison for either supported dtype:

```bash
git show 4c1ddc6d9f38230bad4daa4844219a3ca3765673:vllm/models/hy_v4/nvidia/triton_ihc.py > /tmp/ihc_baseline.py
CUDA_VISIBLE_DEVICES=0 python benchmarks/kernels/benchmark_hy_v4_ihc_pre_compare.py \
  --baseline-source /tmp/ihc_baseline.py --dtype bfloat16
```
